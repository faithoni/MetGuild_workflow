# Workflow for Defining Metabolic niches from Metagenomic Data
---
## Description
This repository contains a reproducible downstream workflow for defining metabolic niches from functionally annotated genome-centric metagenomic data.

The workflow supports feature matrix cleaning, clustering, statistical filtering, correlation analysis, network construction, and generation of network-ready node and edge files.

This repository accompanies:
**Faith I. Oni, Ulisses N. Rocha Year: 2026.** *Genome-Resolved Insights into Microbial Metabolic Niches in a Long-Term Sulfate-Reducing, Benzene-Degrading Community*. **Ecological Informatics.** DOI: [DOI]

## Overview
```bash
This repository provides a modular downstream workflow for defining metabolic niches from functionally annotated genome-centric metagenomic data.

The workflow starts from genome-level functional annotation matrices generated by external tools and supports:

- feature matrix cleaning
- k-optimization
- KMeans/MDS clustering
- hierarchical clustering
- ANOVA or chi-square statistical testing
- feature-vs-feature correlation analysis
- feature-vs-cluster correlation analysis
- cluster-vs-cluster correlation analysis
- network edge list and node attribute generation

The framework is annotation-tool agnostic and can use one or more functional potential datasets, depending on the study design. At least one genome-vs-function matrix is required for downstream analysis.

This repository does **not** perform raw read processing, genome recovery, taxonomic classification, genome annotation, or metabolic model reconstruction. Tools used for those upstream steps are listed under [External tools](#external-tools-used-upstream).
```

## Quick start
Clone the repository and move into it:
```bash
git clone https://github.com/YOUR_USERNAME/niches_workflow.git
cd niches_workflow
```
Create and activate the conda environment:
```bash
conda env create -f environment.yml
conda activate niches_workflow
```
Make the workflow script executable:
```bash
chmod +x run_niches_workflow.sh
```
Run the workflow with your input dataset:
```bash
bash run_niches_workflow.sh data/your_input_file.tsv
```
For example:
```bash
bash run_niches_workflow.sh data/01_DSK_DB.tsv
```

## Input file requirements

The input file can be a .tsv or .csv file.

The dataset must contain a column named:
```bash
Genomes
```
This column is used as the genome/sample identifier throughout the workflow.
The remaining columns should represent genes, pathways, modules, reactions, or other functional features.

## Running with Apptainer/ Singularity

```bash
Build the container:

test the container:
apptainer test niche_workflow.sif

execute:
apptainer exec niche_workflow.sif python --version

run:
apptainer run --bind "$PWD:/project" niche_workflow.sif data/your_input_file.tsv
Example:
apptainer run --bind "$PWD:/project" niche_workflow.sif data/01_DSK_DB.tsv
```
## Workflow steps
```text
The workflow runs the following steps automatically:
| Step | Script                                              | Purpose                                                            |
| ---- | --------------------------------------------------- | ------------------------------------------------------------------ |
| 1    | `01_removing_zero_columns_K_Optimization.py`        | Removes all-zero and all-NaN columns, then performs k-optimization |
| 2    | `02_kmeans_mds_clustering.py`                       | Runs KMeans clustering and MDS visualization                       |
| 3    | `03_hierarchical_clustering.py`                     | Runs hierarchical clustering                                       |
| 4    | `04_ANOVA_testing.py` or `04_chi-square_testing.py` | Performs statistical testing depending on the input filename       |
| 5    | `05_spearman_feature_vs_feature_correlation.py`     | Computes feature-vs-feature Spearman correlations                  |
| 6    | `06_spearman_feature_vs_cluster_correlation.py`     | Computes feature-vs-cluster Spearman correlations                  |
| 7    | `07_spearman_cluster_vs_cluster_correlation.py`     | Computes cluster-vs-cluster Spearman correlations                  |
| 8    | `08_merge_filtered_files.py`                        | Generates network edge lists and node attribute files              |

```

## Output Structure
The workflow automatically creates an output folder using the prefix of the input filename.
For example, this command:
```bash
bash run_niches_workflow.sh data/my_dataset.tsv
```
creates this output folder:
```bash
my_dataset/
```
After a successful run, the output folder will contain:
```bash
my_dataset/
├── manifests/
├── 02_k_optimization/
├── 03_04_clustering/
├── 05_stat_analysis/
├── 06_correlation/
└── 07_network_construction/
```
### The final network files are located in:
```bash
my_dataset/07_network_construction/edge_lists/
my_dataset/07_network_construction/nodes_attributes/
```
## Example datasets

Six example datasets generated using the annotation strategies described in the manuscript can be found in the Example datasets/ folder:
```bash
1. **DSK_DB: Targeted gene/pathway presence-absence matrix**
2. **DSK_P_DB: Targeted pathway completion/proportion matrix**
3. **MAG_KEGG_DB: KEGG module presence-absence matrix**
4. **MAG_KEGG_P_DB: KEGG module completion/proportion matrix**
5. **GSMR_KEGG_DB: Genome reconstruction versus KEGG module matrix**
6. **PROKKA_DB: PROKKA-derived gene presence-absence matrix (excluding hypothetical proteins)**
```
Users may analyze one dataset or several datasets independently.

## Biological feature selection: A critical workflow design step

One of the most important steps in this workflow is the **selection of genes, pathways, or metabolic functions** used to generate at least one functional potential dataset/matrix.
This step is not only a technical preprocessing choice; it is a **biologically defining step** that strongly shapes the interpretation of downstream clustering, statistical testing, correlation analyses, and network construction. The quality and relevance of the final metabolic niche assignments depend heavily on how well the selected features represent the metabolic processes likely to occur in the community under study.

Selection of genes and pathways should therefore be guided by:

- the **community process being investigated**
- **intensive literature review**
- a **comprehensive understanding of the expected metabolic processes** within the system
- prior knowledge of relevant taxa, substrates, intermediates, and environmental conditions

For example, in a community enriched for anaerobic benzene degradation, the selected feature set should emphasize pathways and genes linked to anaerobic aromatic compound activation and degradation, sulfate reduction, hydrogen metabolism, acetate turnover, syntrophic interactions, carbon fixation, and other functions that are biologically plausible in that ecosystem.

Because this workflow is modular, users may generate multiple functional potential datasets using different annotation strategies. However, at least one dataset should be built around a **carefully justified feature set** that is biologically relevant to the community process of interest.

Before running the downstream analysis steps, the user should define:

1. the **ecological or metabolic process of interest**
2. the **key pathways expected to contribute to that process**
3. the **genes, reactions, or modules that best represent those pathways**
4. the **annotation strategy** that will be used to detect them

This knowledge-guided feature selection step is essential for ensuring that the resulting datasets are informative, interpretable, and appropriate for defining metabolic niches.

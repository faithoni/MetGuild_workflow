`# MetGuild-Workflow for Defining Metabolic potential guilds from Metagenomic Data`
---
## Description
This repository contains a reproducible downstream workflow for defining metabolic metguild from functionally annotated genome-centric metagenomic data.

The workflow supports feature matrix cleaning, clustering, statistical filtering, correlation analysis, network construction, and generation of network-ready node and edge files.

This workflow only run steps in Phase I and Phase II. Phase III is not computational but guided by expert knowledge in the interpretation of the network modules as metabolic potential guilds. 

This repository accompanies:
**Faith I. Oni, Ulisses N. Rocha Year: 2026.** *MetGuild: A Genome-Resolved Workflow for Identifying Metabolic Potential Guilds: Application to a Long-Term Sulfate-Reducing Benzene-Degrading Consortium. **Ecological Informatics.** DOI: [DOI]

## Overview
```bash
This repository provides a modular downstream workflow for defining metabolic metguild from functionally annotated genome-centric metagenomic data.

The workflow starts from genome-level functional annotation matrices generated by external tools and supports:

- feature matrix cleaning
- k-optimization
- KMeans/MDS clustering
- hierarchical clustering
- ANOVA or chi-square statistical testing
- feature-vs-feature correlation analysis
- feature-vs-cluster correlation analysis
- cluster-vs-cluster correlation analysis
- network edge list and node attribute generation

The framework is annotation-tool agnostic and can use one or more functional potential datasets, depending on the study design. At least one genome-vs-function matrix is required for downstream analysis.

This repository does **not** perform raw read processing, genome recovery, taxonomic classification, genome annotation, or metabolic model reconstruction. Tools used for those upstream steps are listed under [External tools](#external-tools-used-upstream).
```

## Quick start
Clone the repository and move into it:
```bash
git clone https://github.com/faithoni/metguild_workflow.git
cd metguild_workflow
```
Create and activate the conda environment:
```bash
conda env create -f environment.yml
conda activate metguild_workflow
```
Make the workflow script executable:
```bash
chmod +x run_metguild_workflow.sh
```
Run the workflow with your input dataset:
```bash
bash run_metguild_workflow.sh data/your_input_file.tsv
```
For example:
```bash
bash run_metguild_workflow.sh Example_dataset/matrices/01_DSK_DB.tsv
```
When prompted:
- Select 1 for chi-square or 2 for ANOVA, as appropriate for the analysis.
- Enter Example_taxonomy.csv when asked for the taxonomy path.
## Repository structure

Before running the workflow, the repository should look like this:

```text
metguild_workflow/
├── run_metguild_workflow.sh
├── environment.yml
├── scripts/
│   ├── 01_removing_zero_columns_K_Optimization.py
│   ├── 02_kmeans_mds_clustering.py
│   ├── 03_hierarchical_clustering.py
│   ├── 04_ANOVA_testing.py
│   ├── 04_chi-square_testing.py
│   ├── 05_spearman_feature_vs_feature_correlation.py
│   ├── 06_spearman_feature_vs_cluster_correlation.py
│   ├── 07_spearman_cluster_vs_cluster_correlation.py
│   └── 08_merge_filtered_files.py
└── data/
    └── your_input_file.tsv
```
#### NOTE
MetGuild runs chi-square or ANOVA according to the user’s selection. The workflow inspects feature values and provides a preliminary recommendation; it does not verify the statistical assumptions.

## Input file requirements

The input file can be a .tsv or .csv file.

The dataset must contain a column named:
```bash
Genomes
```
This column is used as the genome/sample identifier throughout the workflow.
The remaining columns should represent genes, pathways, modules, reactions, or other functional features.



## Workflow steps
```text
The workflow runs the following steps automatically:
| Step | Script                                              | Purpose                                                            |
| ---- | --------------------------------------------------- | ------------------------------------------------------------------ |
| 1    | `01_removing_zero_columns_K_Optimization.py`        | Removes all-zero and all-NaN columns, then performs k-optimization |
| 2    | `02_kmeans_mds_clustering.py`                       | Runs KMeans clustering and MDS visualization                       |
| 3    | `03_hierarchical_clustering.py`                     | Runs hierarchical clustering                                       |
| 3b   | `Embedded in run_metguild_workflow.sh`              | run_niches_workflow.sh	Combines clustering assignments with genome taxonomy|
| 4    | `04_ANOVA_testing.py` or `04_chi-square_testing.py` | Performs statistical testing depending on the input filename       |
| 5    | `05_spearman_feature_vs_feature_correlation.py`     | Computes feature-vs-feature Spearman correlations                  |
| 6    | `06_spearman_feature_vs_cluster_correlation.py`     | Computes feature-vs-cluster Spearman correlations                  |
| 7    | `07_spearman_cluster_vs_cluster_correlation.py`     | Computes cluster-vs-cluster Spearman correlations                  |
| 8    | `08_merge_filtered_files.py`                        | Generates network edge lists and node attribute files              |
| 9    | `Embedded in run_metguild_workflow.sh`              | Generates the populated SQLite provenance database and SQL reconstruction dump|

```

## Output Structure
The workflow automatically creates an output folder using the prefix of the input filename.
For example, this command:
```bash
bash run_metguild_workflow.sh data/my_dataset.tsv
```
creates this output folder:
```bash
my_dataset/
```
After a successful run, the output folder will contain:
```bash
my_dataset/
├── manifests/
├── 02_k_optimization/
├── 03_04_clustering/
├── 05_stat_analysis/
├── 06_correlation/
└── 07_network_construction/
```
### The final network files are located in:
```bash
my_dataset/07_network_construction/edge_lists/
my_dataset/07_network_construction/nodes_attributes/
```
## Example datasets

Six example datasets generated using the annotation strategies described in the manuscript can be found in the Example datasets/ folder:
```bash
1. **DSK_DB: Targeted gene/pathway presence-absence matrix**
2. **DSK_P_DB: Targeted pathway completion/proportion matrix**
3. **MAG_KEGG_DB: KEGG module presence-absence matrix**
4. **MAG_KEGG_P_DB: KEGG module completion/proportion matrix**
5. **GSMR_KEGG_DB: Genome reconstruction versus KEGG module matrix**
6. **PROKKA_DB: PROKKA-derived gene presence-absence matrix (excluding hypothetical proteins)**
```
Users may analyze one dataset or several datasets independently.

## Benchmarking
```bash
Benchmarking was performed to evaluate runtime, memory usage, reproducibility, and output stability across datasets of different sizes.
Benchmarking was performed using `/usr/bin/time -v`.

| Dataset | Runtime | Max memory | CPU use | Status |
|---|---:|---:|---:|---|
| `01_DSK_DB.tsv` | 19.07 s | 221 MB | 95% | Completed |
| `02_DSK_P_DB.tsv` | 14.42 s | 218 MB | 93% | Completed |
| `03_MAGs_KEGG_DB.tsv` | 19.78 s | 217 MB | 97% | Completed |
| `04_MAGs_KEGG_P_DB.tsv` | 40.07 s | 229 MB | 84% | Completed |
| `05_GSMR-KEGG_DB.tsv` | 49.01 s | 219 MB | 90% | Completed |
| `06_PROKKA_DB.tsv` | 10 min 04.03 s | 2.90 GB | 99% | Completed |

Example benchmark command:

/usr/bin/time -v bash run_metguild_workflow.sh data/your_input_file.tsv



> Across the six benchmarked datasets, the complete workflow finished successfully for all inputs. Runtime ranged from 14.42 seconds for `02_DSK_P_DB.tsv` to 10 minutes 04.03 seconds for `06_PROKKA_DB.tsv`. Maximum memory usage ranged from approximately 217 MB to 2.90 GB, based on maximum resident set size reported by `/usr/bin/time -v`.

> The `06_PROKKA_DB.tsv` dataset required substantially more runtime and memory than the other datasets, consistent with the larger feature space expected from PROKKA-derived gene presence-absence matrices.
```
